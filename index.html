Data Model

Relational structure for enterprise operations analysis.

This project demonstrates how operational, financial, workforce, and vendor data can be modeled into a relational structure for repeatable analysis.

Core tables

Table Purpose
equipment Asset inventory, lifecycle, cost, type, and assignment attributes.
equipment_usage_logs Runtime, idle time, operator activity, and project-level usage behavior.
maintenance_logs Service events, downtime, maintenance classification, and asset history.
maintenance_invoices Cost records associated with maintenance activity and vendor billing.
employees / regions / vendors Reference entities supporting workforce, geography, and provider relationships.

Example analytical logic

Snippet from idle equipment risk logic demonstrating aggregation, null-safe division, and calculated utilization metrics.


ROUND(
  SUM(u.idle_hours) /
  NULLIF(SUM(u.hours_used + u.idle_hours), 0),
  2
) AS idle_ratio
SQL Analysis Library

Queries organized by business question.

Each query is designed to answer an operational question and demonstrate a specific SQL pattern.

Query Business Question Technique Demonstrated Open
Idle Equipment Risk Detection Which assets show elevated idle time relative to total available time? Aggregation, calculated ratios, null-safe division SQL
High Cost Low Use Equipment Which assets generate cost without corresponding operational usage? Joins, grouping, cost/use comparison SQL
Maintenance Cost by Equipment Which equipment records drive the most maintenance spend? Multi-table joins, invoice aggregation SQL
Equipment Cost vs Actual Use Which assets are least efficient based on cost relative to usage? Subqueries, computed metrics, sorting SQL
Most Expensive Assets Which assets carry the highest combined cost profile? Ranking, aggregation, cost analysis SQL
Least Efficient Assets Which assets have poor cost-to-usage performance? Efficiency ratio logic, ordering, comparative analysis SQL
